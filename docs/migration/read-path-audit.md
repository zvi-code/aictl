# SQL read-path audit — Phase S

This is the read work list required by `ui-rewrite-plan.md:431–448`. Consumer names and classes refer to `docs\migration\consumer-audit.md`. The inventory below records the SQL paths at the time of the audit. The proposed KQL shapes are not measured query plans.

Phase S z1 moved Board, session records and evidence, context inventory, live history, and analytics to named store views. The dashboard no longer calls `board_history.py`, and `live_queries.py` was removed. The dashboard uses the configured store's reader for both local-node and fleet history. Local runtime data, such as process gauges, remains separate.

Phase S z2 moved language-model and MCP event scans to `events.page`, and moved the live feed reader and cluster health metrics into `stores/kusto`. External Copilot, Cursor, and VS Code databases remain read-only inputs.

Phase S z3 deleted the legacy dashboard projections, SQL adapter, and parity tests. References below are historical.

## Order and rules

Do the plugin base, tables and expected-failure B6 test first. Then use one domain per PR. This is the order for reads; the write-path audit controls the order for writers. Keep old HTTP payloads in Phase S, including routes that will go in Phase 6. Run fixed-data old/new parity before removing each SQL implementation. These constraints come from the plan at `ui-rewrite-plan.md:229–250,344–352,442–455`.

| PR | Domain | Reason for order |
|---:|---|---|
| 1 | Session and node identity | Establish node-qualified keys, current winners and scope. The CLI has a bounded reader that can verify those rules before the board uses them (`src\aictl\dashboard\node_views.py:162–180,391–443`). |
| 2 | Request usage, cost and latency | Migrate the shared board cube and usage fallback before callers compute turn/loop or session-row totals (`src\aictl\dashboard\board_api.py:810–831,1753–1788,3710–3727`). |
| 3 | Execution activity, tools and errors | Use the same session scope and request rates. This separates structured tool activity from transcript text and context evidence (`src\aictl\dashboard\board_api.py:2168–2265,2328–2380,2475–2510`). |
| 4 | Session sequence and evidence | Use the prior session/call views. Test text retention, author selection and response order separately from aggregates (`src\aictl\dashboard\board_api.py:4619–4806`; `src\aictl\dashboard\session_evidence.py:73–106`). |
| 5 | File inventory, artifacts and session search | Use the session/call/sequence views for search hits and eligibility; keep content lookup and file permissions independent (`src\aictl\dashboard\session_record.py:522–561,590–703`). |

| 9 | Retire the SQL adapters | Remove the memo, connection and in-memory projection shims after the last domain moves. Restart and external database work is tracked below; no product query should still use the shim (`src\aictl\dashboard\live_queries.py:57–128`; `src\aictl\dashboard\board_history.py:282–380`). |

**Notation.** **Current** means `summarize arg_max(version, *) by node_id, <logical key>` (or a measured equivalent materialized view), then reject tombstones. Only immutable filters can precede it. **Filter** means a parameterized `where` and bounded `project` plus sort/limit as indicated. **Aggregate** means `summarize` over deduplicated rows; use exact counts where the contract requires exact counts. **Series** means `make-series` or an explicit grid with `summarize … by bin_at(...)`; preserve bucket start, nulls, and incomplete last bucket. Version/key selection belongs to the plugin, not the HTTP handler. These constraints follow K1, K6 and B2–B4 (`ui-rewrite-plan.md:229–247`). Do not assume that a native Kusto branch and a SQLite fallback already return identical results.

#### Recorded fixtures for read regressions

Use the `kusto_store` pytest fixture for read tests. Seed it with `kusto_store.insert("requests", **{"session_id": "s", "ts": 100.0, "input_tokens": 7})` and pass `kusto_store` to the board or `kusto_store.history_store` to the HTTP snapshot. Use canonical `stores\kusto\tables.py` fields. Seed a separate row in a `*_text` table when the view needs retained text. Use fixed times and explicit node IDs when the test concerns fleet scope. The fixture replaces the pytest sandbox root with a stable marker in requests and restores it in responses.

The fixture runs the production `KustoReader`. In record mode it adds schema-typed `let <table> = datatable(...)[...];` declarations after the query parameters. These shadow the stored tables. Bare and bracket-quoted table references are supported. Explicit `table()`, `materialized_view()`, `database()` and `cluster()` references are rejected rather than reading shared data. Where a `union` used implicit source names, R1 now labels each branch explicitly: Kusto gives shadowed expressions generated names such as `union_arg0`. Large tables use compressed query parameters and are expanded and typed in the inline expression before the view runs. The 100,000-request wire-budget test's literal query was 43,555,692 characters; the engine's limit is 2,097,152. Packing preserves all the seeded rows without changing the view or ingesting data. The fixture sends only query requests, with hardline read-only mode, to `example/aictl_perf_test`.

```powershell
# Set this before pytest redirects HOME and USERPROFILE.
$env:AZURE_CONFIG_DIR = "$env:USERPROFILE\.azure"
$env:AICTL_PARITY_DB = "aictl_perf_test"
$env:AICTL_RECORD_KUSTO = "1"
python -m pytest -q test\test_usage_figures.py

# Replay is the default and needs no Kusto credentials.
Remove-Item Env:AICTL_RECORD_KUSTO,Env:AICTL_PARITY_DB
python -m pytest -q test\test_usage_figures.py
```

Commit `test\recordings\kusto\<test module>\views.jsonl.gz` with the test. The lookup key covers the actual query, typed fixture data, and bound parameters. A missing recording fails; it does not fall back to the network. Record one process per module. To force a fresh capture rather than reuse unchanged responses, remove that module's tape before recording it. The fixture derives a separate in-memory projection only for callers still on the R2 SQL path; migrated R1 views never use that projection.

Nonempty seeded data exposed two read differences: interval usage returned no rows when the dynamic parameter and expanded column shared the same name; application totals with no start time were filtered out before projection. R1 now names the expanded column explicitly and uses the legacy unknown-start rule. The original prompt, skill, and application-total assertions stay in place.

The board now sorts the set of requested turn keys before binding it, so the same keys produce the same query parameters in every process. Response ordering assertions did not need to change. Artifact fixtures write LF explicitly so Windows byte counts match the asserted bytes. Tests dedicated to SQLite `ProjectStores` now check which facts are visible across stores, after a split, or while another store writes, without routing those assertions through the Kusto board. Mixed session-search tests still exercise the legacy listing and assert the original search result and detail counts, with their migrated reads fed by the same input dictionaries.

unchanged. `db reset` prompts unless `--yes` is set and clears only aictl
tables. `db trim-text` soft-deletes retained text for the configured node,
with a dry run and optional age cutoff; it leaves the metadata tables intact.
`db compact` is removed. The old board action reports that Kusto retention
replaces compaction. Catalog sync and validation use the plugin writer and
reader. ADX policy, table inventory, ingestion capacity, and cluster
diagnostics management reads run in the plugin, not in the HTTP handlers.

**Remaining reads.** `rg -n 'sqlite3\.connect|\._conn\(|PRAGMA|execute_mgmt|HistoryProjection\('`
